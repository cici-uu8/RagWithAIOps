## Production Safety Boundaries

### Configuration Defaults (Hard Boundaries)

The following configuration defaults are **production safety boundaries** and must not be changed without explicit eval evidence and approval:

```python
# app/config.py — Production defaults (do NOT change without gate passage)
rag_session_memory_mode = "off"           # Memory integration: off by default
tool_result_offload_enabled = False       # AIOps tool offload: disabled by default
pdf_agent_tools_enabled = False           # PDF page/table tools: disabled by default
rag_query_rewrite_mode = "off"            # Query rewrite: off by default
rag_default_retrieval_mode = "dense_only" # Retrieval mode: dense_only by default
```

**Rationale**:
- `rag_session_memory_mode=off`: Session memory scaffold plus C4 request-level RAG prompt integration are implemented as default-off/shadow/local behavior. Enabling active without calibration still risks prompt pollution, hallucination surface expansion, and uncontrolled token cost.
- `tool_result_offload_enabled=false`: Tool result offload store exists but thresholds are not calibrated against real long sessions or AIOps multi-step tool results. Enabling without testing risks breaking audit trails and eval reproducibility.
- `pdf_agent_tools_enabled=false`: `read_document_page` / `extract_document_table` are implemented through `PdfDocumentToolProvider`. Real indexed-PDF smoke, no-leak checks, E1 rerun, and PDF page/table eval rerun passed on 2026-06-09. G7 local-only enablement is approved and active via local `.env`; source defaults, staging, and production remain disabled.
- `rag_query_rewrite_mode=off`: R2 query rewrite is not implemented. Current 18/18 pass does not provide rewrite evidence; eval showed RAG-06/07 were eval-expectation issues, not retrieval-expression problems.
- `rag_default_retrieval_mode=dense_only`: R1 retrieval-mode comparison runner exists but has only run on 2-sample comparison. Changing to `hybrid` requires stable evalset, acceptable latency, and no regression on citation/wrong_scope.

### SQLite Growth Risk

`SessionMemoryStore` and `SessionToolResultOffloadStore` will grow unbounded if enabled without cleanup:
- `logs/enterprise_chat_sessions.sqlite`: `session_memory_snapshots`, `session_memory_archives`, `tool_result_offloads` tables
- **Before enabling C4/C5 in production**: implement TTL cleanup (e.g., archive snapshots > 30 days, offloads > 7 days)
- Add capacity limits, owner cleanup, and DB size monitoring; set alert at 500MB

### Audit Trail Integrity

Tool result offload (C5) replaces full tool results with summaries in prompt. **Audit must retain original full results**:
- Current implementation keeps `past_steps` string-compatible and writes the full original result to `SessionToolResultOffloadStore`; the prompt/state path only carries a summary plus `tool_result:*` ref
- Offloaded content must remain owner-queryable for audit/debug; `get_result(result_ref, owner_id=...)` is the current evidence recovery path
- Production active still needs a trace/audit linkage check proving that `tool_result:*` refs can be resolved during eval and incident review
- Do not enable offload if full-result retention is not verified; summary-only offload is not acceptable

### Permission Bypass Risk

PDF Agent tools (B4) bypass must not occur:
- `read_document_page` / `extract_document_table` must call `DocumentAccessService.can_read_document(context, document)` **before** reading artifacts
- ToolGateway must inject `RequestContext` with verified `CurrentUser` before tool execution
- Cross-department doc_id leakage: tools must not expose doc_id from departments the user cannot see
- Permission-denied responses must not leak title, content snippets, table data, artifact paths, or source file paths

### Configuration Drift Prevention

New config switches must default to off/shadow:
- Any new `*_mode` config: default `"off"`
- Any new `*_enabled` config: default `False`
- Any new retrieval/rerank/generation mode: shadow first, eval second, active last
- Production config review: quarterly audit that defaults remain off unless gate passed
