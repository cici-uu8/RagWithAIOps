# 主仓库边界清理任务

## 1. 任务定位

本任务只确认主 checkout 中哪些文件应该保留、迁移或继续待确认。

硬边界：

- 不删除任何文件。
- 不移动任何文件。
- 不在主 checkout 继续开发。
- 不把主 checkout 切到其他分支。
- 不把 runtime 输出、实验输出、计划实验目录直接提交到主线。

当前只读观察到：

```text
main_checkout = /Users/cici/oncall agent/super_biz_agent_py-release-2026-03-21
current_branch = enterprise3
state = dirty
safe_worktree_for_docs = /Users/cici/oncall agent/.worktrees/agent-eval-assets
```

说明：此前口径里提到过 `enterprise2`，但本次只读 `git status --short --branch` 显示当前主 checkout 是 `enterprise3`。无论是 `enterprise2` 还是 `enterprise3`，原则都一样：主 checkout 不是 main，不继续写入；新工作开独立 worktree。

这些不在本任务第一批逐项判断范围内。建议后续按类别开二级盘点：

| 类别 | 处理原则 |
|---|---|
| 运行时产物 | 只确认是否需要归档；不提交主线。 |
| eval/report 输出 | 优先保留为证据；迁移到对应 worktree 或归档目录。 |
| docs 规划文件 | 通过 `docs/plan_registry.md` / plan governance 决定 active / historical / archived。 |
| 原始资料 | 保留并迁移到资料归档，不删除。 |
| finetuning workspace | 保留为 planning-only / shadow asset，和生产代码分离。 |

## 4. 建议执行顺序

1. 先确认两个独立目录：
   - `plan-governance-experiment/`
   - `super_biz_agent_py-plan-update/`
2. 再确认 release 目录下 8 个根配置/治理文件：
   - `.gitattributes`
   - `.github/workflows/ci.yml`
   - `.plangraph.ignore`
   - `.plangraph.yml`
   - `BACKLOG.md`
   - `CLOSEOUT.md`
   - `GEMINI.md`
   - `KIMI.md`
3. 再做二级脏状态分类：
   - runtime / local DB / pid / uploads / volumes
   - eval reports
   - docs planning
   - raw source materials
   - llm_finetuning_workspace

## 5. 迁移候选规则

| 目标 | 适用对象 |
|---|---|
| 独立 workspace | `plan-governance-experiment/`、`super_biz_agent_py-plan-update/` 这类完整目录。 |
| `.worktrees/<branch>` | 后续还要继续开发或验证的 SuperBizAgent 分支。 |
| `docs/` | `CLOSEOUT.md`、Backlog、治理配置说明等需要成为项目文档的材料。 |
| 外部归档目录 | 原始资料、历史报告、运行时输出。 |
| 保持主 checkout 但不提交 | 临时本地配置、未确认工具状态。 |

## 6. 明确禁止

- 禁止 `rm -rf`。
- 禁止 `git clean`。
- 禁止 `git reset --hard`。
- 禁止 `git checkout -- <path>`。
- 禁止直接 pop/apply stash 来“清理”。
- 禁止把 `.env`、`.venv`、runtime DB、uploads、volumes 误提交。

## 7. 当前推荐结论

先不动文件。

本任务的第一步应该是让用户确认以下二选一/三选一判断：

| path | 推荐判断 |
|---|---|
| `plan-governance-experiment/` | 迁移到独立 workspace / archive，不留在 oncall 父目录。 |
| `super_biz_agent_py-plan-update/` | 先保留并确认来源；如果仍有价值，转成正式 worktree 或归档。 |
| `.gitattributes` | 候选保留，但应单独评审后提交。 |
| `.github/workflows/ci.yml` | 候选保留，但必须单独 CI 评审。 |
| `.plangraph.*` | 候选保留，但依赖 PlanGraph 路线是否继续。 |
| `BACKLOG.md` | 候选保留，需决定是否采用根 backlog。 |
| `CLOSEOUT.md` | 优先保留，建议迁移到正式 closeout 文档位置。 |
| `GEMINI.md` / `KIMI.md` | 候选保留，需决定多 agent provider 文档是否纳入项目治理。 |

确认后再执行迁移；执行迁移也必须在单独 worktree / 单独提交中完成。

## 8. AuditEvidenceVerifier 后续入口

主仓库边界清理与 `AuditEvidenceVerifier` 不应混在同一提交。

如果继续实现，建议另开 worktree，例如：

```text
/Users/cici/oncall agent/.worktrees/audit-evidence-verifier
branch = codex/audit-evidence-verifier
```

第一步不是写代码，而是从 `docs/Agent评测门禁Scorecard.md` 的 `G-P0-AUDIT-EVIDENCE` 抽出验收规则：

- 哪些 event type 必须有 `trace_id` / `request_id`。
- 哪些 allow / deny / block 必须有 `decision` / `reason`。
- 哪些 tool / database / human-review 事件必须有 `resource_id` / `tool_id` / `confirmation_id` / `review_id`。
- 哪些字段缺失是 P0，哪些只是 P1 / observation。
