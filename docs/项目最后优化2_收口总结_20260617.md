## 架构合规总结

本轮所有新增能力严格遵守 `docs/项目完整架构.md` 的架构铁律：

### ✅ 铁律 4.1：所有用户请求必须进入 RequestGateway
- ✅ P0a Memory Operator routes 走 `RequestGateway.execute(...)`
- ✅ P1 Database Catalog routes 走 `RequestGateway`
- ✅ P2 Ops Metrics routes 走 `RequestGateway`

### ✅ 铁律 4.2：所有工具执行必须进入 ToolGateway
- ✅ P1 sample rows 通过 `ToolGateway.execute(...)` 执行
- ✅ Stage 3 `retrieve_database_context` 注册到 ToolGateway

### ✅ 铁律 4.3：所有权限判断必须进入访问与资源 Module
- ✅ P0a admin 权限检查：`require_admin_user`
- ✅ P1 列权限过滤：`DatabaseCapabilityCatalogService.get_authorized_columns(...)`
- ✅ P2 admin scope：`OpsMetricsAdapter`

### ✅ 铁律 4.6：数据库能力必须经过 SafeSqlKernel 和 DB permission
- ✅ P1 sample rows 走 `SafeSqlKernel`
- ✅ Stage 3 context tool 不直接查询数据库（由 Agent 调用 safe_select）
- ✅ Stage 4 error hints 不改变安全边界

### ✅ 审计分层
- ✅ RequestGateway 写请求审计（`request_started` / `request_completed` / `request_failed`）
- ✅ Service 写领域审计（`memory_review` / `tool_execution` / `database_query`）

## 完整能力闭环

### Memory 可见性层
```
Operator 通过 admin console "Memory Operator" 入口
   ↓
查看 Review Queue（待审批的 candidate/conflict）
   ↓
Approve/Reject（写 memory_review audit）
   ↓
查看 Validation Status（Gate A.2 计数器）
   ↓
预览 Deprecation Plan（owner-scoped，不执行）
```

**边界**：Memory 仍默认 `off`，此 UI 仅供 operator review。

---

### 数据库可见性层
```
Agent 收到用户问题："查询最近进厂的员工"
   ↓
Agent 调用 retrieve_database_context("查询最近进厂记录")
   ↓
返回上下文：
- 相关示例：F01（SQL: select ... where direction='entry' ...）
- 表结构：factory_access_events 已授权列
- 说明：employee_name 会脱敏
   ↓
Agent 参考示例生成 SQL
   ↓
Agent 调用 database_demo.safe_select 执行 SQL
   ↓
（如果 SQL 不安全）SafeSqlKernel 拦截 + 返回友好提示
   ↓
Agent 理解错误，重新生成 SQL
   ↓
执行成功 → 返回结果（脱敏后）
```

**Operator 视角**：
```
Admin 通过 admin console "Database Catalog" 入口
   ↓
查看数据库列表（sandbox_sales / database_demo / 已授权 MySQL）
   ↓
选择数据库 → 查看表列表
   ↓
选择表 → 查看已授权列 + sample rows（前 10 行）
   ↓
Sample rows 通过 ToolGateway + SafeSqlKernel 执行
```

---

### 运维可见性层
```
Admin 通过 admin console "Ops Dashboard" 入口
   ↓
查看总览卡片（总请求/成功率/P50/P95延迟）
   ↓
查看 Top Users/Routes/Tools 排行
   ↓
查看请求趋势 Timeline（按时间桶聚合）
   ↓
查看最近失败列表（含 failure_semantics 和 recovered 状态）
   ↓
切换时间范围（1h/24h/7d）
```

**边界**：不含成本统计（P3 未触发）。
