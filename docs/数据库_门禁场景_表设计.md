# 数据库门禁场景表设计

日期: 2026-06-16

状态: 数据库能力升级 v2 Stage 1 已实现。当前只替换 sandbox 示例数据，不新增 DB route，不改变 SQL 安全边界。

## 设计目标

将默认 `sandbox_sales` 示例从订单/告警切换为更贴近企业内部运维的门禁记录场景。第一阶段只提供 deterministic sandbox 数据和 registry allowlist，后续 Q-SQL/context 工具继续复用既有 `ToolGateway`、`SafeSqlKernel`、`DatabasePermissionFilter` 和 audit 链路。

保留 `database_id="sandbox_sales"`，避免扩散到权限资源、gateway、测试 fixture 和既有 DB operation 链路。

## 表 1: factory_access_events

用途: 员工进出厂门记录。

```sql
CREATE TABLE factory_access_events (
    event_id INTEGER PRIMARY KEY,
    employee_id TEXT NOT NULL,
    employee_name TEXT NOT NULL,
    department_name TEXT NOT NULL,
    direction TEXT NOT NULL,
    gate_name TEXT NOT NULL,
    event_time TEXT NOT NULL,
    badge_id TEXT,
    raw_device_payload TEXT
);
```

字段策略:

| 字段 | 是否允许查询 | 敏感 | mask | 说明 |
|---|---:|---:|---|---|
| event_id | 是 | 否 |  | 事件 ID |
| employee_id | 是 | 否 |  | 员工编号 |
| employee_name | 是 | 是 | `name` | 员工姓名，结果中显示姓氏加星号 |
| department_name | 是 | 否 |  | 部门名称 |
| direction | 是 | 否 |  | `entry` 或 `exit` |
| gate_name | 是 | 否 |  | 厂门名称 |
| event_time | 是 | 否 |  | 事件时间 |
| badge_id | 是 | 是 | `badge` | 门禁卡号，结果中显示前 3 后 3 |
| raw_device_payload | 否 | 是 | `redact` | 设备原始数据，禁止查询 |

## 表 2: building_access_events

用途: 员工进出楼栋、楼层和门禁点记录。

```sql
CREATE TABLE building_access_events (
    event_id INTEGER PRIMARY KEY,
    employee_id TEXT NOT NULL,
    employee_name TEXT NOT NULL,
    department_name TEXT NOT NULL,
    building_name TEXT NOT NULL,
    floor_name TEXT NOT NULL,
    direction TEXT NOT NULL,
    access_point_name TEXT NOT NULL,
    event_time TEXT NOT NULL,
    device_id TEXT,
    raw_device_payload TEXT
);
```

字段策略:

| 字段 | 是否允许查询 | 敏感 | mask | 说明 |
|---|---:|---:|---|---|
| event_id | 是 | 否 |  | 事件 ID |
| employee_id | 是 | 否 |  | 员工编号 |
| employee_name | 是 | 是 | `name` | 员工姓名，结果中显示姓氏加星号 |
| department_name | 是 | 否 |  | 部门名称 |
| building_name | 是 | 否 |  | 楼栋名称 |
| floor_name | 是 | 否 |  | 楼层 |
| direction | 是 | 否 |  | `entry` 或 `exit` |
| access_point_name | 是 | 否 |  | 门禁点名称 |
| event_time | 是 | 否 |  | 事件时间 |
| device_id | 是 | 是 | `redact` | 设备 ID，结果中全打码 |
| raw_device_payload | 否 | 是 | `redact` | 设备原始数据，禁止查询 |

## 种子数据

`app/enterprise/database/sandbox.py` 创建 24 条 deterministic seed:

- `factory_access_events`: 12 条，覆盖进厂/出厂、东门/北门/西门/南门、研发部/运营部/安保部/制造部/运维部、正常工作时间与夜间进入。
- `building_access_events`: 12 条，覆盖流数楼、运营楼、安保楼、制造楼、数据中心，以及正常和夜间门禁事件。

这些数据用于 sandbox demo、权限测试、safe-select 测试和后续 Q-SQL 示例，不代表真实生产数据。

## 验证重点

- registry 只暴露两张门禁表。
- `employee_name`、`badge_id`、`device_id` 按对应 mask 脱敏。
- `raw_device_payload` 为 `allowed=False`，查询时触发 unauthorized column。
- 既有 SafeSqlKernel 限制不变: 禁止 `SELECT *`、JOIN、子查询、函数、DML/DDL。
