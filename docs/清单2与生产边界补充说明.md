# 清单 2.1 与生产安全边界补充说明

日期：2026-06-09

## 背景

清单 2.1 已完成 E1 第一切片、C4 RAG session memory default-off 接入、C5 AIOps tool-result offload default-off 接入、B4 PDF Agent 工具 default-off 接入、D1 routing shadow 诊断字段。A3 query rewrite shadow 是条件触发项，当前没有 retrieval-expression 失败证据，因此暂停。

本说明只处理一个问题：这些开发项能否长期运行。结论是：**核心风险已经被识别并写入清单 / PROJECT_STATE / 默认配置，但当前只能作为 active 前置门禁，不能当成生产已解决。**

## 当前硬边界

以下默认值必须保持关闭或保守：

```python
rag_session_memory_mode = "off"
tool_result_offload_enabled = False
pdf_agent_tools_enabled = False
rag_query_rewrite_mode = "off"
rag_default_retrieval_mode = "dense_only"
```

这些默认值不是临时保守，而是生产安全边界。任何生产启用都必须先补齐对应 eval、观测、清理、权限和 rollback 记录。

## 用户补充风险核对

| 风险 | 是否考虑 | 当前事实 | 长期运行门禁 |
|---|---|---|---|
| memory/offload SQLite 表持续增长 | 已考虑 | `SessionMemoryStore.cleanup_expired(...)` 和 `SessionToolResultOffloadStore.cleanup_expired(...)` 已实现，并在 RAG prompt 读取 / AIOps offload 写入时 opportunistic cleanup | 仍需定时清理任务、容量上限、owner 级清理入口、DB size 指标和告警 |
| memory summary 过期影响回答判断 | 已考虑 | C4 会按 `rag_session_memory_snapshot_ttl_seconds` 判断 stale，过期 snapshot 不注入 active prompt | 仍需长会话 shadow 校准，确认 TTL 与真实会话节奏匹配 |
| prompt 注入增加成本和幻觉面 | 已考虑 | 默认 `off`；active 文本有长度上限；注入标题明确写“仅作上下文，不是资料依据”；`source_ref` / citation 字段会被净化 | 仍需 token 成本观测、幻觉回归、权限/scope/citation 扩展 eval |
| tool offload 只保留摘要破坏审计/eval | 已考虑 | 当前不是 summary-only：prompt/past_steps 只放摘要和 `tool_result:*` ref，完整原文存在 owner-checked `SessionToolResultOffloadStore` | 仍需真实 AIOps 长日志 smoke、阈值校准、trace/audit/result_ref 回查验证和 retention 策略 |
| PDF 工具通过 `doc_id/page` 泄露文档 | 已考虑 | 工具 schema 只暴露 `doc_id/page/table_id`；`RequestContext` 由后端 ToolGateway 注入；读取 artifact 前调用 `DocumentAccessService.can_read_document(...)`；拒绝响应不泄露标题/正文/表格/路径 | 仍需真实 indexed-PDF smoke、E1 复跑、PDF page/table eval 复跑和无泄漏回归 |
| evalset 过期导致 18/18 虚高 | 已考虑 | 18/18 current-scope 已明确是 3 文档小样本 baseline；E1 30q 也是小样本护栏 | 新 KB、权限模型、PDF 工具、memory active、检索默认值变化后必须扩展/复跑 eval |
| 配置误开 | 已考虑 | PROJECT_STATE 写明 C4/C5/B4/A3 默认禁用边界 | 生产启用前必须有显式配置变更、门禁证据、rollback/enablement 记录 |

## 不能误解的点

- 已实现 `cleanup_expired(...)` 不等于已经有生产级定时清理和容量监控。
- RAG session memory 能注入 prompt 不等于可以生产 active；默认仍是 `off`。
- AIOps offload 能保存完整原文不等于审计链路已经生产验收；还需要证明 `tool_result:*` ref 能在 eval / incident review 中稳定回查。
- PDF 工具已有权限门不等于可以开放给生产 Agent；仍需真实 PDF、真实权限、真实 eval 的回归。
- 18/18 和 E1 当前结果只能说明当前小样本没有暴露问题，不能说明长期质量。

## 当前执行结论

清单 2.1 的非条件开发项可以视为阶段完成，但生产 active 仍被以下门禁拦住：

1. TTL / 清理任务 / DB size 观测。
2. 长会话 shadow 与 prompt 成本/幻觉评估。
3. AIOps offload result_ref 到审计/eval 的回查验证。
4. PDF 工具真实 indexed-PDF smoke 与无泄漏回归。
5. evalset 扩展与周期性复跑机制。
6. 每个能力单独的 rollback / enablement 记录。

因此，后续开发应优先补生产门禁，而不是直接打开 `active` 或扩大默认工具能力。
