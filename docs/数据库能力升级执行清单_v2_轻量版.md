# 数据库能力升级执行清单 v2（轻量且架构对齐版）

## 目标

将数据库能力从"安全工具调用"升级为"schema-aware 的数据库问答"，**第一版只做生成前上下文增强，不做 Milvus 索引和自动修正**。

## 核心原则

- ✅ 增强生成前上下文（schema、描述、示例、策略）
- ✅ 保持执行层安全边界（allowlist、safe SQL kernel、审计、确认）
- ✅ 第一版轻量化：内存检索、不做自动修正、不引入新依赖
- ✅ 复用现有 `ToolGateway` / `ToolExecutionFacade` / `ResourceCatalogService` / `DatabasePermissionFilter` / `AuditService`
- ❌ 不放开 JOIN/子查询/函数/SELECT * 限制
- ❌ 不在 safe_sql.py 层做业务编排
- ❌ 不直接把新工具塞进 `RagAgentService.tools`
- ❌ 不新增并行权限层或独立 HTTP route

## 与完整版的差异

| 项目 | 完整版（v1） | 轻量版（v2） |
|------|-------------|-------------|
| 示例检索 | Milvus 向量检索 | 内存 + 规则匹配 |
| 自动修正 | 最多重试 2 次 | **不做**，只返回结构化错误提示 |
| 工具接入 | 未强制说明 ToolGateway 闭环 | **通过 ToolGateway + ToolExecutionFacade 暴露** |
| 权限过滤 | 易被写成独立逻辑 | **复用 DatabasePermissionFilter** |
| ResourceCatalog | 后置或未说明 | **同阶段注册 tool/table/column 资源** |
| 阶段数 | 7 阶段 22 步 | **4 个实施阶段 11 步 + 1 个可选交付步骤** |
| 新增依赖 | Milvus、索引管理 | **无**（复用现有 registry） |
| 交付周期 | 4-6 周 | **1-2 周** |

### S1.1 设计新的表结构

**目标：** 从订单/告警改为员工进出厂/进出楼记录，贴合企业运维场景。

**执行步骤：**

1. 设计两张表：

   **表 1：factory_access_events（员工进出厂记录）**
   ```sql
   CREATE TABLE factory_access_events (
       event_id INTEGER PRIMARY KEY,
       employee_id TEXT NOT NULL,        -- 员工编号（如 E001）
       employee_name TEXT NOT NULL,      -- 员工姓名（可脱敏）
       department_name TEXT NOT NULL,    -- 部门
       direction TEXT NOT NULL,          -- entry / exit
       gate_name TEXT NOT NULL,          -- 厂门名称（如 "东门", "北门"）
       event_time TEXT NOT NULL,         -- ISO 8601 格式
       badge_id TEXT,                    -- 门禁卡号（敏感字段）
       raw_device_payload TEXT           -- 设备原始数据（禁止查询）
   );
   ```

   **表 2：building_access_events（员工进出楼记录）**
   ```sql
   CREATE TABLE building_access_events (
       event_id INTEGER PRIMARY KEY,
       employee_id TEXT NOT NULL,
       employee_name TEXT NOT NULL,
       department_name TEXT NOT NULL,
       building_name TEXT NOT NULL,      -- 楼名（如 "流数楼"）
       floor_name TEXT NOT NULL,         -- 楼层（如 "1F", "3F"）
       direction TEXT NOT NULL,          -- entry / exit
       access_point_name TEXT NOT NULL,  -- 门禁点名称
       event_time TEXT NOT NULL,
       device_id TEXT,                   -- 设备 ID（敏感字段）
       raw_device_payload TEXT           -- 设备原始数据（禁止查询）
   );
   ```

2. 设计字段权限策略：
   - **允许查询：** event_id, employee_id, employee_name, department_name, direction, gate_name/building_name/floor_name, access_point_name, event_time
   - **敏感字段（脱敏）：** employee_name（显示姓氏+*，如"张*"）, badge_id（显示前3后3，如"ABC***XYZ"）
   - **禁止查询：** raw_device_payload（设备原始数据可能包含指纹、人脸等生物特征）
