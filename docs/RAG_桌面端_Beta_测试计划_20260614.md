# RAG 桌面端 Beta 测试计划

日期：2026-06-14

状态：`desktop_beta_plan_ready`

## 1. 目标

本计划用于组织 3-5 个内部用户进行电脑端 Beta 试运行。它基于当前桌面端验收结果执行真实使用观察，不改变运行默认值，不扩大到移动端，不把 MCP 稳定性问题混入主流程验收。

输入基线：

```text
桌面端验收 = docs/项目全功能验收_20260613.md
内部 Beta runbook = docs/RAG_Internal_Beta_Runbook_20260612.md
用户材料 = docs/RAG_Beta_生产试运行用户材料.md
反馈日志 = docs/RAG_Beta_User_Feedback_Log.md
反馈 schema = docs/schemas/rag_user_feedback.schema.json
```

当前桌面端状态：

```text
desktop_acceptance = 51 PASS / 0 FAIL / 2 PARTIAL
mobile_scope = out_of_scope
known_fail = none
separate_track = MCP stability
known_partial = normal AIOps MCP diagnosis / memory ingestion via MCP discovery
latest_technical_smoke = 2026-06-16 21/21
```

固定默认值：

```text
rag_default_retrieval_mode = dense_only
rag_query_rewrite_mode = off
rerank_enabled = false
rag_top_k = 3
PDF_AGENT_TOOLS_ENABLED = false
```

## 2. Beta 口径

可以进入本轮 Beta 的桌面端主流程：

- 登录、登出、profile。
- 普通聊天、RAG 问答、SSE 流式回答、会话历史。
- 文件上传、文件管理列表、处理状态、健康检查、误报标记。
- 权限申请、我的申请、管理员审批。
- 数据库 catalog、safe-select、operation prepare / confirmation 边界。
- Admin console 的用户、角色、grant、audit、Trace 查询和对比。
- 执行看板的页面加载、Chat Stream timeline、终态展示。

本轮明确不作为通过/失败判定的范围：

- 移动端 / 390px 响应式体验。
- 普通 AIOps MCP 诊断完整链路。
- Memory ingestion 依赖 MCP discovery 的完整链路。
- MCP CLS / Monitor 服务稳定性修复。
- GA 上线、Answer 50q、agent_behavior 验收。
- hybrid、rerank、query rewrite、top_k、prompt 默认变更。

## 3. 参与角色

最小 3 人，推荐 4 人，最多 5 人。

| 用户 | 角色 | 必选 | 主要验证面 | 账号建议 |
|---|---|---|---|---|
| U1 | Oncall / SRE | 是 | 真实故障问答、会话、source_ref、文件上传 | 普通用户 |
| U2 | DBA / 数据库运维 | 是 | Redis/MySQL runbook、数据库 catalog/safe-select/confirmation | 普通用户 |
| U3 | 文档 / PDF review 用户 | 是 | PDF/文档问答、上传后可见性、文档健康检查 | 普通用户 |
| U4 | 管理员 / 部门管理员 | 推荐 | 权限审批、grant、audit、Trace 查询 | admin 或 department_admin |
| U5 | Beta owner / 观察员 | 可选 | 反馈质量、每日分流、周度 review | 不要求业务操作 |

用户选择标准：

- 必须使用电脑端浏览器。
- 使用真实工作表达，不按 evalset 背题。
- 愿意记录原始 query、答案、召回文档和缺失事实。
- 不粘贴密码、token、客户隐私、生产敏感数据。

## 5. 1 周执行节奏

### Day 0 - 准备

- 确认修复已提交或已准备提交，且不包含 `uv.lock` 的无关变更。
- 部署测试环境或确认本地/内网环境稳定。
- 跑启动 smoke。
- 建立本轮用户名单和反馈负责人。
- 给用户发送 `docs/RAG_Beta_生产试运行用户材料.md`。
- 在 `docs/RAG_Beta_User_Feedback_Log.md` 建立本轮 Week section。

### Day 1 - 入场和主流程试用

每个普通用户至少完成：

- 登录。
- 发起 2 条真实问答。
- 查看会话历史。
- 上传 1 个小型 Markdown/TXT 文档。
- 打开文件管理，确认上传文档可见。
- 查看该文档健康检查详情。

管理员用户至少完成：

- 查看 admin console。
- 查看 pending permission requests。
- 查询 1 个 Trace。

### Day 2-4 - 真实问题观察

每个业务用户每天提交 3-5 条真实 query。

建议覆盖：

| 用户 | 每日建议问题 |
|---|---|
| U1 Oncall/SRE | CPU、磁盘、服务不可用、PVC、Pod Pending/NotReady、告警处理 |
| U2 DBA | Redis 内存、MySQL 慢查询、数据库操作边界、只读查询 |
| U3 文档/PDF | PDF 表格、页码、报告条款、上传文档后的问答 |
| U4 Admin | 权限申请审批、grant 创建/撤销、audit/Trace 查看 |

每天记录：

```text
total_queries_today
feedback_count_today
retrieval_success_count
answer_issue_count
source_ref_issue_count
permission_scope_issue_count
document_upload_visible_failures
database_boundary_failures
```

### Day 5 - 分流复现

Beta owner 和 technical reviewer 处理所有 `queue_for_review`：

1. 权限/scope 问题优先，任何 confirmed 都暂停扩大。
2. source_ref 不可回查优先，重复出现则开 citation/source_ref bug。
3. 文档上传后不可见如果复现，视为 P0 回归。
4. 数据库越权、DML/DDL 未阻断如果复现，视为安全问题。
5. answer/retrieval 问题必须累计和可复现，不能单条就改默认值。

### Day 6-7 - 周度 Review

用 `docs/RAG_Beta_User_Feedback_Log.md` 的 Week 模板做 review。

输出决策：

```text
continue_beta = true / false
expand_beta_users = true / false
open_answer_revisit = true / false
open_retrieval_triage = true / false
open_security_bug = true / false
open_mcp_diagnostic = separate_track_only
```

## 9. MCP 专项边界

本轮 Beta 允许用户看到 AIOps 入口，但不要求普通 MCP 诊断链路作为通过项。

记录规则：

- 如果用户碰到 AIOps 普通诊断失败，记录为 `mcp_known_issue_observed`，不计入桌面主流程失败率。
- 如果高风险 AIOps 进入 human-review gate，按现有通过能力记录。
- 如果 Memory ingestion 因 MCP discovery 失败，不把它作为 RAG/文件管理主流程失败。

下一轮 MCP 专项目标：

```text
make start-cls start-monitor status-mcp stable
normal /api/aiops diagnosis stable
memory ingestion event ordering stable
```

## 11. 禁止事项

Beta 期间默认不做：

- 不处理移动端。
- 不把 MCP 稳定性修复混入 Beta 主流程验收。
- 不把 AI 模拟反馈写成 confirmed 用户反馈。
- 不提交本地 `.env`。
- 不提交 `uv.lock`，除非先确认依赖确实变化且需要纳入本轮。
- 不创建 Answer 50q。
- 不进入 agent_behavior acceptance。
- 不把 OpenJudge/RAGAS 作为主 gate。
- 不启用 hybrid、rerank、query rewrite。
- 不因单条反馈修改全局 prompt、top_k 或 retrieval 默认值。
